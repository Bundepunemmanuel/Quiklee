# Quiklee

Calculators, converters, and meanings — one real, static HTML file per search query, built for Vercel.

## Live structure (repo root, flat — no folders)

```
index.html                → homepage
calculators.html           → generated hub page (all calculators, grouped)
converters.html             → generated hub page (all converters, grouped)
meanings.html                → generated hub page (all meanings, grouped)

bmi-calculator.html            → generated tool page (one of 26)
tip-calculator.html             → generated tool page
...22 more generated tool pages...

calculators-data.js       → source data: one entry per calculator (edit this)
converters-data.js         → source data: one entry per converter (edit this)
meanings-data.js            → source data: one entry per meaning (edit this)

page-template.html         → shell template for tool pages (don't need to touch)
hub-template.html           → shell template for hub pages (don't need to touch)
render-lib.js                → shared HTML-building functions used by build.js

build.js                   → generates ALL .html pages + vercel.json + sitemap.xml
main.js                     → client-side only: search box + calculator form logic
style.css                    → shared design system

vercel.json                 → auto-generated by build.js (clean URLs config)
sitemap.xml                  → auto-generated by build.js
robots.txt                   → static, points to sitemap
```

## How it actually works now (important change from earlier version)

Every tool page — `bmi-calculator.html`, `tip-calculator.html`, all 26 — is a **real, complete
static HTML file** with its title, meta description, H1, form, explainer text, and related
links already baked in. Nothing is filled in by JavaScript. This is what lets Google index each
page immediately on first crawl, instead of waiting on a second render pass.

`vercel.json` uses Vercel's `cleanUrls: true`, so `bmi-calculator.html` is automatically served
at `/bmi-calculator` — no manual routing list needed.

`main.js` still runs in the browser, but only for two things: the search box, and running the
actual calculation when someone submits a form. It has nothing to do with page content anymore.

## Adding a new tool (you still never hand-write HTML)

1. Open the relevant data file (`calculators-data.js`, `converters-data.js`, or
   `meanings-data.js`) and copy an existing entry as a starting point.
2. Fill in: `slug`, `cluster`, `clusterLabel`, `title`, `metaDescription`, `h1`, `intro`,
   `type` (`"form"` or `"info"`), the fields/content, `explainer`/`caveat`, and `related` (an
   array of other slugs to link to — link both ways for a real cluster).
3. If it's a new **calculation type**, add one `case` to the `calculate()` function in `main.js`
   (this is the only place actual math logic lives).
4. Run:
   ```
   node build.js
   ```
   This regenerates every page, `vercel.json`, and `sitemap.xml` in one shot.
5. Commit and push. Nothing else to do.

## Deploying

1. Push this whole folder to a GitHub repo (flat, as shown above).
2. Import the repo in Vercel.
3. **Set these two Build & Development settings in the Vercel project** (Settings → Build &
   Development Settings) — this is what makes new tools go live automatically:
   - **Build Command:** `node build.js`
   - **Output Directory:** `.`

   With this set, every `git push` triggers Vercel to run `build.js` on its own servers before
   deploying — regenerating every tool page, both hub pages, `vercel.json`, and `sitemap.xml`
   from whatever is currently in the `*-data.js` files. You never run the build yourself and
   never generate a file locally — edit a data file, push, and the URL (and its sitemap entry)
   exists on the live site a minute later.
4. After it's live: add the site in Google Search Console, submit `sitemap.xml` once, and use
   the URL Inspection tool to request indexing for your first few pages manually — this nudges
   Google's crawler rather than waiting for organic discovery on a brand-new domain. You don't
   need to resubmit the sitemap after that — Google re-checks it periodically on its own, and
   it'll already reflect whatever pages exist at that time since Vercel regenerates it on every
   push.

## What's intentionally not built yet (see conversation for reasoning)

- **Comparisons** section (software/app/product comparisons) — planned as phase 2.
- **Ad/affiliate placements** — left out of the markup entirely for now. When ready, slots
  should go in `page-template.html` (so every tool page gets them at once) without disrupting
  the calculator itself — ads above/below the tool card, never inside or blocking it.
- Country/region-specific BMI pages (`bmi-calculator-[country]`) — pattern is proven with the
  10-page BMI cluster; duplicate the pattern per region only where units or context genuinely
  differ (e.g. US uses lbs/ft-in, not just a copy-pasted page with a country name swapped in).
